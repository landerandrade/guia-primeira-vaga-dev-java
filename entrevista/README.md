# Entrevista Técnica para Dev Java Júnior

A maioria dos devs júnior é reprovado não porque não sabe programar. É reprovado porque não sabe o que vai ser perguntado — e entra em pânico.

---

## Como é o processo típico

Varia por empresa, mas o padrão mais comum é:

1. **Triagem com RH** — perguntas comportamentais, fit cultural, expectativa salarial
2. **Teste técnico** — problema para resolver em casa ou ao vivo (30min–2h)
3. **Entrevista técnica** — conversa sobre o teste + perguntas de fundamentos
4. **Entrevista com gestor** — fit com o time, soft skills

Para júnior, o peso maior é no **teste técnico** e na capacidade de **explicar o que fez**.

---

## O que avaliam no técnico

**Não é só se o código funciona.**

Avaliam:
- Você entende o que está codando ou só copiou de tutorial?
- Consegue nomear variáveis e métodos com clareza?
- Sabe dividir o problema em partes antes de escrever código?
- Pergunta quando não entende o requisito?
- Faz perguntas inteligentes durante o processo?

## Perguntas técnicas mais comuns para Java Júnior

### Orientação a objetos
- Qual a diferença entre classe abstrata e interface?
- O que é encapsulamento? Dê um exemplo prático.
- O que é polimorfismo?
- Qual a diferença entre `==` e `.equals()`?

### Java
- O que é o garbage collector?
- Qual a diferença entre `ArrayList` e `LinkedList`?
- O que são checked e unchecked exceptions?
- O que é imutabilidade? Por que `String` é imutável em Java?
- O que faz o `Optional`? Por que usar?

### Spring Boot
- O que é injeção de dependência? Como o Spring faz isso?
- Qual a diferença entre `@Component`, `@Service`, `@Repository` e `@Controller`?
- O que é um Bean?
- Como funciona o Spring Security básico?
- O que é JPA? Qual a diferença entre `findById` e `getById`?

### Banco de dados
- O que é uma chave primária? E uma chave estrangeira?
- Qual a diferença entre `INNER JOIN` e `LEFT JOIN`?
- O que é uma transação? O que significa ACID?
- O que é índice e quando usar?

### Git
- Qual a diferença entre `merge` e `rebase`?
- O que faz o `git stash`?
- Como resolver um conflito de merge?

## Como se preparar para o teste técnico

**Antes:**
- Leia o enunciado inteiro antes de começar a codar
- Identifique os requisitos funcionais e não-funcionais
- Esboce a estrutura antes de abrir o IDE

**Durante:**
- Commite com frequência e mensagens claras
- Se travar, avance para outra parte e volte
- Prefira código simples e correto a código "inteligente" e com bug

**Depois:**
- Escreva um README explicando como rodar e suas decisões técnicas
- Se não terminou tudo: explique o que faria se tivesse mais tempo

## Perguntas comportamentais (não ignore)

Recrutador técnico sênior sabe que júnior não vai ter todas as respostas técnicas. O que ele quer saber:

- Você aprende rápido?
- Sabe pedir ajuda?
- Lida bem com feedback?
- Vai embora na primeira dificuldade?

Perguntas que aparecem:

- *"Fala de um problema técnico que você teve e como resolveu."*
  Prepare uma história real: qual era o problema, o que você tentou, como resolveu, o que aprendeu.

- *"Qual sua maior dificuldade com programação hoje?"*
  Seja honesto. Mostrar autoconsciência é positivo. Dizer "nenhuma" é vermelho.

- *"Por que Java e não Python/JS?"*
  Tenha uma resposta genuína — não só "porque é o que aprendi".

- *"Como você aprende uma tecnologia nova?"*
  Documentação, projeto prático, comunidade. Não: "assisto YouTube".

## Na hora da entrevista

- Se não souber a resposta: diga o que você sabe sobre o tema e o que faria para descobrir
- Não invente — entrevistador sênior percebe na hora
- Pergunte sobre o time, o projeto, as tecnologias usadas — mostra interesse real
- Perguntar sobre salário na primeira entrevista técnica: evite, espere o RH abordar
